## 第一章 自动化基础

本章明确自动化的边界并掌握文件级操作能力。

### 1.1 自动化的适用场景

**学习目标**：能判断哪些工作值得自动化。

**核心知识点**

- 适合自动化：重复次数多、规则明确、人工操作易出错的流程
- 不适合自动化：一次性任务、规则频繁变化、需要复杂人工判断的工作
- 自动化的收益应大于维护成本，脚本也需要长期维护
- 优先自动化高频且耗时的环节，而不是追求一次性覆盖全流程

**示例**

值得自动化：每月汇总 30 份格式相同的表格
不值得：一次性整理三张图片

**易错点**：为一次性任务编写复杂脚本，投入时间远超手工完成所需。

### 1.2 文件与目录批量操作

**学习目标**：掌握 pathlib 与 shutil 的常用操作。

**核心知识点**

- pathlib.Path 提供面向对象的路径操作，跨平台兼容性优于手写字符串拼接
- 常用操作：exists、iterdir、glob、mkdir、rename、unlink
- shutil 负责复制、移动与删除目录树等高级操作
- 批量操作前先打印将要处理的文件清单，确认无误后再执行

**示例**

```python
from pathlib import Path

src = Path('downloads')
for f in src.glob('*.pdf'):
    f.rename(src / 'pdf' / f.name)
```

**易错点**：直接对目标目录做不可逆的批量删除或覆盖，一旦匹配规则写错损失无法挽回，应先输出清单确认。

### 1.3 命令行参数与日志

**学习目标**：让脚本可配置并具备可追溯的运行记录。

**核心知识点**

- argparse 用于解析命令行参数，支持必填项、默认值与类型转换
- 日志用 logging 模块输出，区分 DEBUG、INFO、WARNING、ERROR 等级别
- 日志应包含时间、级别与关键上下文，便于事后排查
- 脚本应把配置与代码分离，通过参数或配置文件传入运行参数

**示例**

```python
import argparse, logging

logging.basicConfig(level=logging.INFO,
                    format='%(asctime)s [%(levelname)s] %(message)s')
p = argparse.ArgumentParser()
p.add_argument('--input', required=True)
args = p.parse_args()
logging.info('开始处理 %s', args.input)
```

**易错点**：用 print 输出运行信息且不带时间戳，脚本定时运行时无法判断执行时间与失败原因。

## 第二章 常见自动化任务

本章覆盖三类最常见的实战场景。

### 2.1 Excel 与 CSV 批处理

**学习目标**：掌握批量读写表格与合并汇总。

**核心知识点**

- pandas 可一次读取整个目录下的表格并追加合并
- 批量写出时按业务维度拆分文件，便于分发给不同接收方
- openpyxl 适合需要保留格式与公式的场景
- 处理大文件时可分块读取，避免一次性载入内存

**示例**

```python
import pandas as pd, glob

dfs = [pd.read_excel(f) for f in glob.glob('reports/*.xlsx')]
all_df = pd.concat(dfs, ignore_index=True)
all_df.to_excel('summary.xlsx', index=False)
```

**易错点**：合并多表时未对齐列名，直接 concat 会产生大量 NaN 列，应在合并前统一列名。

### 2.2 网页数据采集

**学习目标**：掌握基础的请求与解析方式并遵守规范。

**核心知识点**

- requests 发起 HTTP 请求，需设置超时与请求头以模拟正常访问
- 解析优先使用结构化接口；无接口时用 BeautifulSoup 或 lxml 解析 HTML
- 必须遵守目标站点的 robots.txt 与服务条款，控制请求频率
- 采集结果应本地落盘并去重，避免重复抓取

**示例**

```python
import requests
from bs4 import BeautifulSoup

resp = requests.get(url, timeout=10,
                    headers={'User-Agent': 'Mozilla/5.0'})
soup = BeautifulSoup(resp.text, 'html.parser')
titles = [h.text.strip() for h in soup.select('h2.title')]
```

**易错点**：不设置超时与频率限制，既容易因网络异常卡死脚本，也可能对目标站点造成压力。

### 2.3 定时任务与调度

**学习目标**：掌握脚本的定时执行方式。

**核心知识点**

- 系统计划任务（crontab 或 Windows 任务计划）是简单可靠的定时方案
- schedule 库适合脚本内的轻量定时，但依赖进程常驻
- 调度应避免任务重叠，必要时加文件锁或状态标记
- 任务执行结果应留下日志与告警，失败需能被及时发现

**示例**

```bash
# 每天 8:00 执行
0 8 * * * /usr/bin/python3 /opt/scripts/report.py >> /var/log/report.log 2>&1
```

**易错点**：任务执行时间可能超过调度间隔，导致多个实例并发运行并互相覆盖结果。

## 第三章 工程化与稳定性

本章让脚本从能用走向可长期依赖。

### 3.1 异常处理与重试

**学习目标**：掌握让脚本在异常下仍能稳定运行的写法。

**核心知识点**

- 捕获异常要具体，避免笼统地捕获 Exception 掩盖真实问题
- 网络类操作应实现带退避的重试，限定最大次数
- 批量处理中单个元素失败不应中断整体流程，应记录并继续
- 脚本退出码应能反映执行结果，便于调度系统判断成败

**示例**

```python
import time

for attempt in range(3):
    try:
        data = fetch(url)
        break
    except Exception as e:
        if attempt == 2: raise
        time.sleep(2 ** attempt)
```

**易错点**：批量任务遇到一条脏数据就整体退出，导致前面已处理的部分与后续都陷入不确定状态。

### 3.2 配置与密钥管理

**学习目标**：避免凭据硬编码在脚本里。

**核心知识点**

- 配置可通过环境变量或配置文件注入，代码中不出现真实凭据
- 密钥应存放在受控的密钥管理服务中，而不是随代码提交到仓库
- 配置文件加入版本控制忽略清单，防止误提交
- 不同环境使用不同配置，避免测试配置误连生产

**示例**

```python
import os
api_key = os.environ.get('API_KEY')
if not api_key:
    raise SystemExit('缺少环境变量 API_KEY')
```

**易错点**：把数据库密码直接写在脚本里并提交到仓库，凭据泄露后影响难以估计。

### 3.3 打包与分发

**学习目标**：掌握把脚本交付给他人的方式。

**核心知识点**

- 通过 requirements.txt 固定依赖版本，保证他人环境可复现
- 虚拟环境隔离依赖，避免与其他项目冲突
- PyInstaller 可打包为独立可执行文件，方便无 Python 环境的机器使用
- README 中说明依赖安装方式、参数用法与常见问题

**示例**

```bash
python -m venv venv
pip freeze > requirements.txt
pyinstaller --onefile report.py
```

**易错点**：只提供脚本不提供依赖说明，他人运行报错后需要反复沟通才能跑起来。

## 综合练习

### 单项选择题

**1. 以下哪项最适合通过脚本自动化？**

- A. 一次性整理三张图片
- B. 每月汇总 30 份格式相同的表格
- C. 规则每天变化的工作
- D. 需要复杂人工判断的审核

**答案**：B

**解析**：自动化适合重复次数多、规则明确、人工易出错的流程，一次性或规则频繁变化的任务收益很低。

**对应知识点**：自动化场景

**2. Python 中面向对象、跨平台友好的路径操作应使用？**

- A. os.path 字符串拼接
- B. pathlib.Path
- C. open 的完整路径字符串
- D. subprocess 调用命令行

**答案**：B

**解析**：pathlib.Path 提供面向对象的路径操作，能自动适配不同操作系统的分隔符，可读性与可维护性更好。

**对应知识点**：文件操作

**3. 解析命令行参数应使用哪个模块？**

- A. sys
- B. os
- C. argparse
- D. logging

**答案**：C

**解析**：argparse 支持必填参数、默认值与类型转换，并能自动生成帮助信息。

**对应知识点**：命令行参数

**4. 网络请求实现重试时，必须同时设置什么？**

- A. 最大重试次数与退避等待
- B. 更多的请求头
- C. 更长的 URL
- D. 更大的线程数

**答案**：A

**解析**：重试需限定最大次数并采用退避策略，否则在下游故障时会造成流量放大与长时间阻塞。

**对应知识点**：异常重试

**5. 关于脚本中的密钥管理，推荐的做法是？**

- A. 直接写在脚本里方便维护
- B. 通过环境变量或密钥管理服务注入，配置加入忽略清单
- C. 提交到代码仓库便于团队共享
- D. 写在注释里

**答案**：B

**解析**：凭据应通过环境变量或受控的密钥服务注入，并确保配置文件不会被提交到仓库。

**对应知识点**：密钥管理

### 判断题

**1. 批量处理数据时，遇到单条脏数据应当立即让整个脚本退出。**

**答案**：错误

**解析**：错误。应捕获并记录该条异常后继续处理，避免一条脏数据导致整体任务失败。

**对应知识点**：异常处理

**2. 定时任务的执行时间可能超过调度间隔，需要通过加锁避免多个实例并发运行。**

**答案**：正确

**解析**：正确。任务重叠会造成资源竞争与结果互相覆盖，应加文件锁或状态标记防止并发执行。

**对应知识点**：定时调度

**3. 采集网页数据时无需考虑目标站点的 robots.txt 与服务条款。**

**答案**：错误

**解析**：错误。采集应遵守目标站点的 robots.txt 与服务条款，并控制请求频率，避免造成压力与合规风险。

**对应知识点**：数据采集规范
