# Java 设计模式实战

> 本文件为「知序学堂」课程知识库资料，供课程 AI 助教检索与问答使用。

## 课程简介

用真实场景讲清 23 种设计模式的意图、实现与适用边界。

本课程先建立设计原则的认知基础，再按创建型、结构型、行为型三类展开，每种模式都结合可运行的 Java 代码与业务场景，最后分析 Spring 框架中设计模式的实际运用。

---

## 第一章 设计模式基础

本章说明设计模式要解决什么问题，以及在什么前提下才值得引入。

### 1.1 为什么需要设计模式

**学习目标**：理解设计模式是经验的复用，而不是必须套用的模板。

**核心知识点**

- 设计模式是可复用的面向对象设计经验，描述的是「问题—方案」的对应关系
- 模式的价值在于让代码更易扩展与维护，而不是让代码更短
- 滥用模式会让系统变得抽象层过多、难以阅读，属于典型的过度设计
- 引入模式的前提是变化点已经明确，模式是为变化做准备

**示例**

没有模式：订单支付写成一长串 if-else 分支
有模式：抽象出 PaymentStrategy 接口，新增支付方式只加一个实现类

**易错点**：为「将来可能扩展」而预先套用大量模式，实际需求并未变化，反而增加理解成本。

### 1.2 SOLID 原则

**学习目标**：掌握五条面向对象设计原则并能识别违反场景。

**核心知识点**

- 单一职责 SRP：一个类只应有一个引起它变化的原因
- 开闭原则 OCP：对扩展开放、对修改关闭，通过抽象与多态实现
- 里氏替换 LSP：子类应当能替换父类而不破坏程序正确性
- 接口隔离 ISP 与依赖倒置 DIP：接口要小而专，高层模块不应依赖低层实现而应依赖抽象

**示例**

```java
// 违反 DIP：直接 new 具体实现
private MysqlUserDao dao = new MysqlUserDao();
// 遵循 DIP：依赖接口，由外部注入
private UserDao dao;
```

**易错点**：把 DIP 理解成「必须用接口」，实际上核心是依赖抽象而非依赖细节，抽象也可以是抽象类。

### 1.3 设计模式的分类

**学习目标**：建立 23 种模式的整体地图，便于按问题检索。

**核心知识点**

- 创建型 5 种：单例、工厂方法、抽象工厂、建造者、原型，解决对象创建的问题
- 结构型 7 种：代理、装饰器、适配器、桥接、组合、外观、享元，解决类与对象的组合问题
- 行为型 11 种：策略、模板方法、观察者、责任链、命令、状态、中介者、迭代器、访问者、备忘录、解释器，解决对象间职责分配与通信问题
- 学习顺序建议先掌握单例、工厂、策略、模板方法、观察者、代理这几种高频模式

**示例**

按意图记忆：创建 → 结构 → 行为
按问题检索：对象创建看创建型，接口不兼容看适配器，算法可替换看策略

**易错点**：只背模式名字与 UML 结构，遇到实际场景仍无法判断该用哪个模式。

## 第二章 创建型与结构型模式

本章解决「对象怎么创建」与「类怎么组合」两类问题。

### 2.1 单例与工厂

**学习目标**：掌握线程安全单例的写法与三种工厂的区别。

**核心知识点**

- 枚举单例是实现简单且天然防反射与序列化破坏的推荐写法
- 双重检查锁单例中 volatile 不可省略，它防止指令重排序导致拿到未初始化对象
- 简单工厂用一个方法按参数返回对象，工厂方法把创建延迟到子类，抽象工厂创建一族相关产品
- 工厂模式的收益是把创建逻辑集中，调用方只依赖抽象产品

**示例**

```java
public enum Singleton {
    INSTANCE;
    public void doWork() { }
}
Singleton.INSTANCE.doWork();
```

**易错点**：双重检查锁里漏写 volatile，在特定重排序下其他线程可能读到非空但未完成构造的对象。

### 2.2 建造者与原型

**学习目标**：会用建造者消除长参数列表，理解原型模式的深浅拷贝差异。

**核心知识点**

- 建造者模式适合参数多且可选的场景，通过链式调用提升可读性
- 建造者与构造方法相比，能避免顺序混淆与大量重载构造器
- 原型模式通过拷贝已有对象创建新对象，适合创建成本高的对象
- 浅拷贝只复制基本类型与引用地址，深拷贝需要递归复制引用对象

**示例**

```java
User user = User.builder()
        .name("张三")
        .age(20)
        .email("a@b.com")
        .build();
```

**易错点**：以为 clone() 是深拷贝，默认的 Object.clone() 是浅拷贝，引用字段仍指向同一对象。

### 2.3 代理、装饰器与适配器

**学习目标**：能区分三种结构相似但意图不同的模式。

**核心知识点**

- 代理模式在不改变接口的前提下控制对目标对象的访问，常用于权限、日志、事务
- 装饰器模式在不改变接口的前提下动态为对象增加职责，可以层层叠加
- 适配器模式把不兼容的接口转换成期望的接口，解决的是接口不匹配的问题
- 三者都持有目标对象引用，区别在意图：控制访问、增强功能、转换接口

**示例**

```java
@Transactional
public void transfer() {
    // Spring 通过动态代理在方法前后织入开启与提交事务的逻辑
}
```

**易错点**：把装饰器与代理混用，装饰器关注功能叠加而代理关注访问控制，混用会让类层次难以维护。

## 第三章 行为型模式与实战

本章关注对象之间的职责分配，并落到框架源码中的真实运用。

### 3.1 策略与模板方法

**学习目标**：会用策略消除分支，用模板方法固定流程骨架。

**核心知识点**

- 策略模式把一组可互换的算法封装为独立类，调用方持有策略接口
- 策略模式能替代大量 if-else 分支，新增算法无需修改调用方
- 模板方法在抽象类中定义算法骨架，把可变步骤延迟到子类实现
- 策略关注整个算法的替换，模板方法关注流程中若干步骤的替换

**示例**

```java
public interface PayStrategy {
    void pay(BigDecimal amount);
}
// 调用方只依赖接口，新增支付方式只加实现类
payStrategy.pay(amount);
```

**易错点**：策略类过多时若没有统一的上下文与工厂管理，调用方仍需自行判断该 new 哪个策略，分支只是被搬了位置。

### 3.2 观察者与责任链

**学习目标**：理解一对多通知与链式处理两种协作方式。

**核心知识点**

- 观察者模式在被观察者状态变化时通知所有订阅者，实现发布订阅解耦
- 观察者模式的风险是通知链过长或循环通知，需要做好异常隔离
- 责任链模式把处理者串成链，请求沿链传递直到被处理或走完全链
- 责任链的经典应用是过滤器、拦截器、审批流，可通过配置动态调整顺序

**示例**

```java
public interface OrderHandler {
    void handle(OrderContext ctx, OrderHandler next);
}
// 校验 → 库存 → 优惠 → 支付，按链条依次执行
```

**易错点**：责任链中某个节点抛异常会导致后续节点全部中断，应在节点内捕获并记录，或明确约定中断语义。

### 3.3 Spring 中的设计模式

**学习目标**：能在框架源码中识别常见模式的落地方式。

**核心知识点**

- 工厂模式：BeanFactory 与 ApplicationContext 负责创建与管理 Bean
- 单例模式：Spring 默认以单例方式管理 Bean，因此 Bean 必须设计为无状态
- 代理模式：AOP 通过 JDK 动态代理或 CGLIB 代理实现事务、日志、权限织入
- 模板方法与责任链：JdbcTemplate 定义流程骨架，HandlerExecutionChain 串起拦截器

**示例**

```java
// 单例 Bean 若不是无状态，会出现并发安全问题
@Service
public class OrderService {
    private int counter; // 危险：共享可变状态
}
```

**易错点**：在单例 Bean 中定义可变的成员变量，会在并发请求下互相污染数据。

## 综合练习

### 单项选择题

**1. 开闭原则 OCP 的核心含义是？**

- A. 类应当只保留一个方法
- B. 对扩展开放、对修改关闭
- C. 子类必须能替换父类
- D. 高层模块必须直接依赖低层实现

**答案**：B

**解析**：开闭原则要求系统在新增功能时通过扩展实现，而不修改已有代码，通常依赖抽象与多态达成。

**对应知识点**：SOLID 原则

**2. 以下哪种单例实现方式能天然防止反射与反序列化破坏？**

- A. 饿汉式
- B. 懒汉式
- C. 双重检查锁
- D. 枚举

**答案**：D

**解析**：枚举由 JVM 保证实例唯一，反射无法创建枚举实例，序列化也会保持单例，是最简洁安全的实现。

**对应知识点**：单例模式

**3. 双重检查锁单例中，实例字段为什么必须加 volatile？**

- A. 保证可见性即可，与有序性无关
- B. 防止指令重排序导致其他线程拿到未初始化完成的对象
- C. 为了通过编译检查
- D. 为了让实例可以序列化

**答案**：B

**解析**：对象创建包含分配内存、初始化、赋引用三步，可能被重排序，volatile 禁止重排序从而避免其他线程读到半成品对象。

**对应知识点**：单例模式

**4. 为不兼容的接口提供转换以适配调用方，这说的是哪个模式？**

- A. 代理模式
- B. 装饰器模式
- C. 适配器模式
- D. 外观模式

**答案**：C

**解析**：适配器模式用于把已有接口转换成期望的接口；代理关注访问控制，装饰器关注功能增强。

**对应知识点**：结构型模式辨析

**5. 用一组可互换的算法类替换大量 if-else 分支，应采用哪个模式？**

- A. 模板方法
- B. 策略模式
- C. 责任链模式
- D. 观察者模式

**答案**：B

**解析**：策略模式把算法族封装为独立策略类，调用方持有策略接口，新增算法无需修改原有分支逻辑。

**对应知识点**：策略模式

### 判断题

**1. 策略模式与模板方法的区别之一是：策略替换整个算法，模板方法只替换流程中的若干步骤。**

**答案**：正确

**解析**：正确。策略模式在运行时整体替换算法实现，模板方法由抽象类固定流程骨架、子类实现可变步骤。

**对应知识点**：模式辨析

**2. Spring 默认以单例方式管理 Bean，因此在单例 Bean 中定义可变成员变量是安全的。**

**答案**：错误

**解析**：错误。单例 Bean 被多个请求共享，可变成员变量会产生并发安全问题，单例 Bean 应保持无状态。

**对应知识点**：Spring 中的模式

**3. 为避免将来可能的变化而预先引入大量设计模式，是值得推荐的做法。**

**答案**：错误

**解析**：错误。变化点尚未明确时套用模式属于过度设计，会增加抽象层次与维护成本。

**对应知识点**：模式使用边界
