# Java 虚拟机性能调优

> 本文件为「知序学堂」课程知识库资料，供课程 AI 助教检索与问答使用。

## 课程简介

理解 JVM 内存结构、垃圾回收机制，并掌握线上性能问题的排查方法。

本课程讲解 JVM 运行时数据区与对象的内存布局，深入垃圾回收算法与主流收集器的取舍，最后落到常用的调优参数、监控工具以及内存泄漏与 OOM 的排查流程。

---

## 第一章 JVM 内存与对象

本章建立 JVM 内存模型的基本认知，理解对象从创建到布局的全过程。

### 1.1 运行时数据区

**学习目标**：能说清各内存区域的职责与线程归属。

**核心知识点**

- 线程私有：程序计数器、虚拟机栈、本地方法栈
- 线程共享：堆、方法区（JDK 8 之后方法区的实现是元空间 Metaspace）
- 堆是垃圾回收的主要区域，按分代思想分为新生代与老年代
- 运行时常量池在 JDK 8 后已移到堆中，字符串常量池也随之进入堆

**示例**

```bash
java -XX:+PrintFlagsFinal -version | grep HeapSize
```

**易错点**：以为虚拟机栈也会发生垃圾回收，实际上栈随线程生命周期自动分配与释放，不需要 GC。

### 1.2 对象创建与内存布局

**学习目标**：理解对象创建流程与对象在内存中的三部分结构。

**核心知识点**

- 对象创建流程：类加载检查 → 分配内存 → 初始化零值 → 设置对象头 → 执行构造方法
- 对象在内存中由对象头、实例数据、对齐填充三部分组成
- 对象头包含 Mark Word（存哈希码、GC 年龄、锁状态）与类型指针
- TLAB 线程本地分配缓冲让每个线程在私有区域分配对象，减少指针碰撞的同步开销

**示例**

```bash
java -XX:+UseTLAB -XX:TLABSize=256k -version
```

**易错点**：把对象头中的 Mark Word 当成固定不变量，实际上它会随锁升级和 GC 年龄变化而被复用。

### 1.3 内存分配策略

**学习目标**：掌握对象优先在哪里分配，以及大对象与逃逸分析的例外。

**核心知识点**

- 对象优先在 Eden 区分配，Eden 空间不足时触发 Minor GC
- 大对象（超过 -XX:PretenureSizeThreshold）直接进入老年代，避免在新生代反复复制
- 长期存活对象经多次 Minor GC 后晋升老年代，默认阈值为 15
- 逃逸分析可以把未逃逸对象的分配优化到栈上，减少堆压力

**示例**

```bash
java -XX:PretenureSizeThreshold=1048576 -XX:MaxTenuringThreshold=15 -version
```

**易错点**：为减少 Minor GC 而盲目调大新生代，会导致单次 GC 停顿变长，反而影响响应时间。

## 第二章 垃圾回收机制

本章讲清「哪些对象可回收」与「用什么方式回收」两个核心问题。

### 2.1 如何判断对象已死

**学习目标**：理解引用计数与可达性分析的差异。

**核心知识点**

- 引用计数法实现简单，但无法解决对象间循环引用的问题，JVM 未采用
- 可达性分析从 GC Roots 出发向下搜索，不可达的对象即判定为可回收
- GC Roots 包括虚拟机栈中引用的对象、静态变量引用的对象、常量引用的对象等
- 对象被判定死亡后还要经过一次 finalize 筛选，但该机制已不推荐依赖

**示例**

GC Roots 示例：栈帧局部变量表引用的对象、方法区静态属性引用的对象

**易错点**：认为只要对象还有引用计数就不回收，从而在设计缓存时留下大量循环引用结构。

### 2.2 垃圾回收算法

**学习目标**：掌握三种基础算法及其适用场景。

**核心知识点**

- 标记清除：标记可回收对象后直接清除，实现简单但会产生内存碎片
- 复制算法：把存活对象复制到另一块空间，无碎片但浪费空间，适合存活率低的新生代
- 标记整理：标记后把存活对象向一端移动，无碎片但移动成本高，适合老年代
- 分代收集是根据对象存活率差异，对不同区域采用不同算法的组合策略

**示例**

新生代：Eden 与两个 Survivor 区，默认比例 8:1:1，采用复制算法
老年代：采用标记整理或标记清除

**易错点**：把 Survivor 区比例设得过小，会导致对象提前晋升老年代，加速老年代碎片化与 Full GC。

### 2.3 常见垃圾收集器

**学习目标**：能根据延迟与吞吐需求选择收集器。

**核心知识点**

- Serial 单线程收集器，适合客户端或内存很小的场景
- Parallel 吞吐量优先，适合后台批处理任务
- CMS 以最短停顿为目标，采用并发标记清除，存在内存碎片与并发失败风险，JDK 9 后已废弃
- G1 把堆划分为多个 Region 并支持可预测停顿，是 JDK 9 之后的默认收集器；ZGC 与 Shenandoah 面向超低延迟

**示例**

```bash
java -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -version
java -XX:+UseZGC -version
```

**易错点**：看吞吐量选 ZGC，或看延迟选 Parallel，方向反了会导致调优目标与实际收益不符。

## 第三章 调优与问题排查

本章给出可落地的参数清单、监控工具与典型故障排查流程。

### 3.1 常用 JVM 参数

**学习目标**：掌握堆、栈、GC 与日志相关的核心参数。

**核心知识点**

- 堆容量：-Xms 与 -Xmx 建议设为相同值，避免运行期反复扩容缩容
- 新生代：-Xmn 或 -XX:NewRatio 控制新生代与老年代比例
- GC 日志：-Xlog:gc* 输出 GC 详情，是分析停顿原因的第一手材料
- 栈与元空间：-Xss 设置线程栈大小，-XX:MaxMetaspaceSize 限制元空间上限

**示例**

```bash
java -Xms2g -Xmx2g -Xmn1g -Xss1m \
  -XX:MaxMetaspaceSize=256m \
  -Xlog:gc*:file=gc.log:time,uptime -jar app.jar
```

**易错点**：只设 -Xmx 不设 -Xms，容器环境下堆频繁伸缩会带来额外停顿与资源抖动。

### 3.2 监控工具

**学习目标**：能用命令行工具快速定位 CPU 高、GC 频繁等问题。

**核心知识点**

- jps 列出 Java 进程与 pid，是排查的第一步
- jstat -gcutil 观察各区使用率与 GC 次数、耗时
- jmap -histo 查看对象统计，jmap -dump 导出堆快照用于离线分析
- jstack 导出线程栈，用于定位死锁与 CPU 飙高的热点线程

**示例**

```bash
jps -l
jstat -gcutil 12345 1000
jstack 12345 > stack.txt
jmap -dump:live,format=b,file=heap.hprof 12345
```

**易错点**：在生产环境直接执行 jmap -dump 会触发 STW，可能造成秒级停顿，应优先用 jmap -histo 或预留的采集通道。

### 3.3 内存泄漏与 OOM 排查

**学习目标**：掌握从现象到根因的完整排查链路。

**核心知识点**

- 先区分是内存泄漏（对象无法回收、持续增长）还是单纯内存不足（堆设置过小）
- 抓取堆快照后按对象数量与占用排序，定位增长最快的类
- 常见泄漏源：静态集合持续 put、ThreadLocal 未 remove、监听器未注销、连接与流未关闭
- 参数 -XX:+HeapDumpOnOutOfMemoryError 可在 OOM 时自动落盘，避免错过现场

**示例**

```bash
java -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/data/dump -jar app.jar
```

**易错点**：看到 OOM 就先把堆调大，只是把问题延后，真正原因可能是持续泄漏而未解决。

## 综合练习

### 单项选择题

**1. 以下哪个区域是线程共享的？**

- A. 程序计数器
- B. 虚拟机栈
- C. 堆
- D. 本地方法栈

**答案**：C

**解析**：堆与方法区是线程共享的，程序计数器、虚拟机栈、本地方法栈都是线程私有的。

**对应知识点**：运行时数据区

**2. JVM 判断对象是否可回收采用的是哪种方式？**

- A. 引用计数法
- B. 可达性分析
- C. 标记整理
- D. 逃逸分析

**答案**：B

**解析**：JVM 采用可达性分析，从 GC Roots 出发搜索，不可达的对象才判定为可回收，从而解决了循环引用问题。

**对应知识点**：对象存活判定

**3. 新生代采用的垃圾回收算法是？**

- A. 标记清除
- B. 标记整理
- C. 复制算法
- D. 分代收集

**答案**：C

**解析**：新生代对象存活率低，采用复制算法，把存活对象复制到 Survivor 区，代价小且不产生碎片。

**对应知识点**：回收算法

**4. JDK 9 之后 HotSpot 的默认垃圾收集器是？**

- A. Serial
- B. Parallel
- C. CMS
- D. G1

**答案**：D

**解析**：G1 在 JDK 9 之后成为默认收集器，它把堆划分为 Region 并支持可预测停顿；CMS 已在 JDK 9 废弃。

**对应知识点**：垃圾收集器

**5. 用于观察各区使用率与 GC 次数、耗时的工具是？**

- A. jps
- B. jstat
- C. jstack
- D. jmap -histo

**答案**：B

**解析**：jstat -gcutil 可以周期性输出各区使用率、GC 次数与累计耗时，是观察 GC 状况的常用工具。

**对应知识点**：监控工具

### 判断题

**1. 为减少 Minor GC 次数，应当尽量把新生代调得越大越好。**

**答案**：错误

**解析**：错误。新生代过大会让单次 GC 需要扫描与复制的对象更多，停顿时间变长，需要结合延迟目标权衡。

**对应知识点**：内存分配策略

**2. 在生产环境直接执行 jmap -dump 导出堆快照不会影响应用响应。**

**答案**：错误

**解析**：错误。jmap -dump 会触发 STW 停顿，堆越大停顿越久，生产环境应谨慎或通过预置通道采集。

**对应知识点**：排查风险

**3. -Xms 与 -Xmx 设置为相同值，可以避免运行期堆反复扩容缩容带来的额外开销。**

**答案**：正确

**解析**：正确。堆固定后避免了动态伸缩的代价与抖动，是生产环境常见的最佳实践。

**对应知识点**：常用参数
