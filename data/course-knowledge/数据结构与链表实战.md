# 数据结构与链表实战

> 本文件为「知序学堂」课程知识库资料，供课程 AI 助教检索与问答使用。

## 课程简介

从复杂度分析入手，用链表、栈、队列与哈希表打牢数据结构基本功。

本课程先建立复杂度分析的思维方式，对比数组与链表的取舍并手写链表；随后深入双向链表、快慢指针等经典链表算法，最后覆盖栈、队列与哈希表的实现原理与典型应用。

---

## 第一章 复杂度与线性表

本章建立评价数据结构与算法的基本语言。

### 1.1 时间复杂度与空间复杂度

**学习目标**：掌握大 O 表示法并能分析常见操作复杂度。

**核心知识点**

- 大 O 描述的是增长趋势而非精确耗时，忽略常数与低阶项
- 常见量级由快到慢：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
- 分析时关注最坏情况，必要时补充平均情况说明
- 空间复杂度统计额外占用的空间，递归调用栈也要计入

**示例**

数组按下标访问 O(1)
有序数组二分查找 O(log n)
冒泡排序 O(n²)

**易错点**：把 O(1) 理解为「执行一次」，它指的是耗时与数据规模无关，而不是绝对时间固定。

### 1.2 数组与链表对比

**学习目标**：能根据访问模式选择数组或链表。

**核心知识点**

- 数组内存连续，支持 O(1) 随机访问，但中间插入删除需移动元素，为 O(n)
- 链表内存离散，插入删除只需改指针为 O(1)（已定位时），但随机访问为 O(n)
- 数组对 CPU 缓存更友好，实际遍历性能常优于链表
- 需要频繁按索引读取选数组，需要频繁在中间增删选链表

**示例**

读多写少、随机访问为主 → 数组（如 ArrayList）
频繁头尾增删、随机访问少 → 链表（如 LinkedList）

**易错点**：认为链表插入删除一定比数组快，若还需先按索引定位，定位本身已是 O(n)。

### 1.3 单链表实现

**学习目标**：能手写单链表的增删查改。

**核心知识点**

- 节点由值域与指针域组成，头节点指向第一个元素
- 插入需要先找到目标位置的前驱节点，再调整指针顺序
- 删除需要让前驱节点跳过待删节点，并释放该节点
- 引入虚拟头节点（哨兵）可以统一头插、头删的边界处理

**示例**

```java
插入：newNode.next = prev.next; prev.next = newNode;
删除：prev.next = prev.next.next;
```

**易错点**：调整指针顺序写反，先改 prev.next 就丢失了后续链表，导致链表断裂。

## 第二章 链表进阶

本章把基本链表操作组合成高频算法套路。

### 2.1 双向链表与循环链表

**学习目标**：理解带前驱指针与首尾相连的结构差异。

**核心知识点**

- 双向链表每个节点同时保存前驱与后继，支持 O(1) 反向遍历与 O(1) 删除已知节点
- 循环链表尾节点指向头节点，适合环形调度等场景
- 双向链表插入删除需同时维护两条指针，代码更易出错
- Java 的 LinkedList 底层即为双向链表，同时实现了 Deque 接口

**示例**

```java
插入：node.prev.next = newNode; newNode.prev = node.prev;
      newNode.next = node; node.prev = newNode;
```

**易错点**：只更新了一半指针，导致正向遍历正常但反向遍历异常，这类 bug 很难排查。

### 2.2 常见链表算法

**学习目标**：掌握反转、快慢指针等高频技巧。

**核心知识点**

- 链表反转用三指针迭代：prev、curr、next，逐个改变指向
- 快慢指针可求中点、判断环、找环入口，快指针每次走两步、慢指针走一步
- 合并两个有序链表用双指针逐个比较，尾部直接拼接剩余部分
- 删除倒数第 k 个节点可用快慢指针保持 k 步间距一次遍历完成

**示例**

```java
// 迭代反转
while (curr != null) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
return prev;
```

**易错点**：判断环时忘记保存 next 指针，反转过程中会丢失后续节点导致空指针。

### 2.3 链表面试题套路

**学习目标**：建立一套可复用的解题框架。

**核心知识点**

- 先确认是否允许修改原链表，能否借助额外空间
- 画图确认指针变化，避免凭空推断
- 边界情况要覆盖：空链表、单节点、头节点操作、尾节点操作
- 善用虚拟头节点统一边界，减少特判分支

**示例**

解题步骤：画图 → 定义指针 → 处理边界 → 编码 → 用 3 个用例验证

**易错点**：不画图直接写指针代码，容易出现顺序错误与未处理的空指针。

## 第三章 栈、队列与哈希

本章覆盖三类基础容器的实现与应用。

### 3.1 栈与队列的实现

**学习目标**：掌握两种受限线性表的特性与实现方式。

**核心知识点**

- 栈后进先出，只允许在一端操作；队列先进先出，一端进另一端出
- 栈与队列都可用数组或链表实现，数组实现需处理扩容与边界
- 循环队列通过取模复用空间，避免假溢出
- 双端队列 Deque 两端都可进出，可作为栈也可作为队列使用

**示例**

```java
循环队列判满：(tail + 1) % capacity == head
入队：queue[tail] = val; tail = (tail + 1) % capacity;
```

**易错点**：循环队列用 size 计数时就不必牺牲一个空位，否则容易把判满条件写错。

### 3.2 栈的典型应用

**学习目标**：能识别适合用栈解决的问题。

**核心知识点**

- 括号匹配：遇到左括号入栈，遇右括号检查栈顶是否配对
- 表达式求值与中缀转后缀依赖栈保存运算符优先级
- 函数调用栈是栈在系统层面的直接体现，递归深度过大导致栈溢出
- 单调栈用于求解「下一个更大元素」「柱状图最大矩形」等经典问题

**示例**

括号匹配：遍历字符，左括号入栈，右括号与栈顶匹配则出栈，最终栈空即合法

**易错点**：递归深度过大触发栈溢出，应改为迭代或显式使用栈来模拟递归。

### 3.3 哈希表与冲突解决

**学习目标**：理解哈希映射的原理与冲突处理方式。

**核心知识点**

- 哈希表通过哈希函数把键映射到桶下标，平均查找复杂度为 O(1)
- 哈希冲突的解决方式：链地址法与开放寻址法
- 装载因子过高会显著增加冲突，需要及时扩容并重新散列
- 哈希表的键必须可哈希且相等的键必须有相同的哈希值

**示例**

链地址法：每个桶挂一条链表（或红黑树）存放冲突元素
开放寻址法：冲突时按探测序列寻找下一个空槽

**易错点**：重写 equals 却不重写 hashCode，会导致两个「相等」的对象落入不同桶，哈希表查找失效。

## 综合练习

### 单项选择题

**1. 以下时间复杂度量级中，增长最慢的是？**

- A. O(n)
- B. O(log n)
- C. O(n log n)
- D. O(n²)

**答案**：B

**解析**：由快到慢依次为 O(1) < O(log n) < O(n) < O(n log n) < O(n²)，对数级增长最慢。

**对应知识点**：复杂度分析

**2. 数组与链表相比，数组的优势在于？**

- A. 中间插入更快
- B. 支持 O(1) 随机访问
- C. 内存不连续
- D. 无需预分配空间

**答案**：B

**解析**：数组内存连续，可通过下标直接计算地址，实现 O(1) 随机访问；链表的优势在于已定位时的插入删除。

**对应知识点**：数组与链表

**3. 判断单链表是否存在环，最常用的技巧是？**

- A. 递归遍历
- B. 快慢指针
- C. 哈希表计数
- D. 反转链表

**答案**：B

**解析**：快慢指针中快指针每次走两步、慢指针走一步，若存在环两者必然相遇，空间复杂度 O(1)。

**对应知识点**：链表算法

**4. 栈的特性是？**

- A. 先进先出
- B. 后进先出
- C. 随机存取
- D. 双端进出

**答案**：B

**解析**：栈只允许在一端插入和删除，遵循后进先出；先进先出是队列的特性，双端进出是双端队列。

**对应知识点**：栈与队列

**5. 哈希表解决冲突的两种主要方式是？**

- A. 链地址法与开放寻址法
- B. 排序法与二分法
- C. 递归法与迭代法
- D. 分治法与贪心法

**答案**：A

**解析**：链地址法在每个桶上挂链表或红黑树，开放寻址法在冲突时按探测序列寻找下一个空槽。

**对应知识点**：哈希冲突

### 判断题

**1. 链表在中间位置插入元素一定比数组快。**

**答案**：错误

**解析**：错误。若需要先按索引定位到插入点，定位过程本身是 O(n)，此时并不比数组快。

**对应知识点**：结构对比

**2. 只重写 equals 而不重写 hashCode，会导致对象在哈希表中查找失败。**

**答案**：正确

**解析**：正确。相等的对象必须有相同的哈希值，否则会被散列到不同桶，导致无法正确命中。

**对应知识点**：哈希表

**3. 使用虚拟头节点（哨兵）可以统一链表头部的边界处理，减少特判分支。**

**答案**：正确

**解析**：正确。哨兵节点让头插、头删与中间操作的处理逻辑保持一致，能显著简化代码。

**对应知识点**：链表技巧
