# 微服务网关与容错

> 本文件为「知序学堂」课程知识库资料，供课程 AI 助教检索与问答使用。

## 课程简介

掌握微服务架构中网关的路由鉴权能力，以及熔断、限流、降级等容错手段。

本课程讲解网关在微服务体系中的职责与选型，深入路由断言、过滤器与全局鉴权；随后系统分析雪崩效应与熔断、降级、限流的实现方式，最后扩展到链路追踪与灰度发布等服务治理能力。

## 第一章 微服务网关

本章说明网关为什么是微服务的统一入口，以及如何做路由与鉴权。

### 1.1 网关的职责与选型

**学习目标**：理解网关在架构中的位置与核心能力。

**核心知识点**

- 网关是所有外部流量的统一入口，屏蔽内部服务的地址与数量变化
- 核心职责包括路由转发、鉴权、限流、灰度、日志与协议转换
- 常见选择：Spring Cloud Gateway 基于响应式模型，Zuul 1 为阻塞模型，Nginx 更偏流量入口层
- 网关层不做业务逻辑，只做与业务无关的横切关注点

**示例**

客户端 → 网关（鉴权/限流/路由）→ 用户服务 / 课程服务 / 订单服务

**易错点**：把业务判断（如订单归属校验）写进网关过滤器，会导致业务逻辑分散、难以测试与复用。

### 1.2 路由与断言

**学习目标**：能配置基于路径、方法、请求头的路由规则。

**核心知识点**

- 路由由 id、目标 uri、断言 predicates 与过滤器 filters 三部分组成
- 断言决定请求是否匹配该路由，常用 Path、Method、Header、Query 等
- 多个断言之间是「与」关系，全部满足才命中；多个路由按声明顺序匹配
- 配合服务发现使用 lb:// 前缀可按服务名负载均衡转发

**示例**

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: course-service
          uri: lb://course-service
          predicates:
            - Path=/cs/**
          filters:
            - StripPrefix=1
```

**易错点**：忘记配置 StripPrefix，转发到下游时路径仍带前缀，导致 404。

### 1.3 过滤器与全局鉴权

**学习目标**：会编写网关过滤器并在网关层完成统一鉴权。

**核心知识点**

- 局部过滤器只作用于某条路由，全局过滤器对所有路由生效
- 过滤器分 pre 与 post 两个阶段，可在请求前后修改请求或响应
- 典型鉴权流程：解析并校验 Token → 提取用户信息 → 写入请求头下传下游
- 下游服务信任网关注入的用户头，可通过内网隔离防止绕过网关伪造请求头

**示例**

```java
public class AuthGlobalFilter implements GlobalFilter, Ordered {
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String token = exchange.getRequest().getHeaders().getFirst("Authorization");
        // 校验 token，解析出 userId 后写入下游请求头
        return chain.filter(exchange);
    }
    public int getOrder() { return -100; }
}
```

**易错点**：把 Token 放在 URL 参数里传递，容易被日志与浏览器历史记录泄露，应放在请求头。

## 第二章 服务容错

本章解决「下游挂了怎么办」这一微服务稳定性核心问题。

### 2.1 雪崩效应与容错手段

**学习目标**：理解雪崩的传导链路与常见阻断手段。

**核心知识点**

- 雪崩效应：某个下游服务响应变慢，上游线程被大量占用耗尽，故障沿调用链逐层放大
- 四大容错手段：超时、限流、熔断、降级
- 超时是基础保障，任何远程调用都必须显式设置超时，避免线程被无限期占用
- 舱壁隔离通过为不同依赖分配独立线程池，防止单一依赖拖垮整个应用

**示例**

配置示例：连接超时 1s、读超时 3s、最大重试 1 次
禁止在非幂等接口上自动重试

**易错点**：不设置超时，默认无限等待，一个慢依赖就能把调用方的线程池占满。

### 2.2 熔断与降级

**学习目标**：掌握熔断器的三种状态与降级兜底策略。

**核心知识点**

- 熔断器三态：关闭（正常放行）、打开（直接拒绝）、半开（放少量请求试探恢复情况）
- 熔断触发条件通常基于滑动窗口内的失败率或慢调用比例
- 降级是在依赖不可用时返回兜底结果，保证核心链路可用
- 降级返回的数据应明确标识为兜底数据，避免被误当成真实数据使用

**示例**

```yaml
resilience4j.circuitbreaker:
  instances:
    courseService:
      slidingWindowSize: 20
      failureRateThreshold: 50
      waitDurationInOpenState: 10s
```

**易错点**：熔断打开时间设置过短，下游尚未恢复就反复进入半开试探，会造成持续的无效流量。

### 2.3 限流算法与实践

**学习目标**：掌握四种限流算法的差异与适用场景。

**核心知识点**

- 固定窗口计数简单但存在临界突刺问题，两个窗口交界处可能放行双倍流量
- 滑动窗口把时间切成小格，平滑了临界问题，实现相对简单，是工程常用方案
- 漏桶以恒定速率流出，强行把流量整形为匀速，适合需要稳定输出的场景
- 令牌桶按速率生成令牌，允许一定程度的突发流量，是多数网关的默认选择

**示例**

```yaml
# 令牌桶：capacity 为桶容量，refillRate 为每秒补充令牌数
capacity: 100
refillRate: 50
```

**易错点**：把限流阈值按单机配置，扩容后集群总阈值随之翻倍，应使用集中式限流或按集群总量分摊。

## 第三章 链路治理

本章补齐可观测性与发布能力，让微服务系统可定位、可控制。

### 3.1 分布式链路追踪

**学习目标**：理解 TraceId 与 SpanId 的作用及传播方式。

**核心知识点**

- 一次外部请求对应一个 TraceId，链路上每个调用单元对应一个 Span
- TraceId 需要沿调用链透传，通常通过请求头传递并在日志中输出
- 只有把 TraceId 打进日志，才能从海量日志中捞出同一次请求的全部记录
- 常见实现为 OpenTelemetry、SkyWalking、Zipkin

**示例**

日志格式中加入 traceId 占位：
%d{yyyy-MM-dd HH:mm:ss} [%X{traceId}] [%thread] %-5level %msg%n

**易错点**：只在入口生成 TraceId 但没有透传到下游，导致链路中断，无法串起完整调用关系。

### 3.2 日志聚合与告警

**学习目标**：建立集中式日志与基于指标的告警体系。

**核心知识点**

- 集中式日志把各服务日志统一采集到日志平台，避免逐台登录机器排查
- 指标关注四类信号：延迟、流量、错误率、饱和度
- 告警阈值应基于历史基线与业务峰值设定，避免阈值过低造成告警疲劳
- 告警必须配套处理预案，否则只是把问题换个地方展示

**示例**

关键指标：P99 延迟、错误率、QPS、线程池队列长度、GC 停顿

**易错点**：只关注平均值，忽略了长尾延迟，实际用户体验由 P99 而不是均值决定。

### 3.3 灰度发布

**学习目标**：掌握灰度发布的常见分流维度与回滚策略。

**核心知识点**

- 灰度发布让新版本先承接少量流量，验证通过后再逐步放量
- 分流维度可以是用户 id 哈希、请求头标记、地域或白名单
- 网关层最适合做分流，因为它掌握全部入口流量
- 必须准备好一键回滚，并保证新旧版本接口兼容

**示例**

分流规则：用户 id 取模 100 小于 5 的请求打到新版本
观察指标：错误率、P99 延迟、核心业务转化率

**易错点**：只做流量灰度不做数据兼容，新旧版本写同一份数据时容易产生脏数据。

## 综合练习

### 单项选择题

**1. 微服务网关的核心职责不包括以下哪一项？**

- A. 路由转发
- B. 统一鉴权
- C. 业务订单状态流转
- D. 限流

**答案**：C

**解析**：网关只负责与业务无关的横切关注点，业务订单状态流转属于业务服务内部的职责。

**对应知识点**：网关职责

**2. 熔断器处于哪种状态时会直接拒绝请求？**

- A. 关闭
- B. 打开
- C. 半开
- D. 隔离

**答案**：B

**解析**：熔断器打开状态直接拒绝请求，避免继续调用已经故障的下游；半开状态会放行少量请求试探。

**对应知识点**：熔断器状态

**3. 允许一定突发流量，且是多数网关默认选择的限流算法是？**

- A. 固定窗口计数
- B. 滑动窗口
- C. 漏桶
- D. 令牌桶

**答案**：D

**解析**：令牌桶按固定速率生成令牌并允许桶内积累，因此能容纳一定程度的突发流量，是网关默认方案。

**对应知识点**：限流算法

**4. 固定窗口计数限流的主要缺陷是？**

- A. 实现过于复杂
- B. 存在临界突刺，窗口交界处可能放行双倍流量
- C. 无法统计流量
- D. 只能用于单机

**答案**：B

**解析**：固定窗口在窗口切换的瞬间可能出现前一个窗口末尾与后一个窗口开头的流量叠加，形成双倍突刺。

**对应知识点**：限流算法

**5. 一次外部请求在分布式链路追踪中对应几个 TraceId？**

- A. 一个
- B. 每个服务一个
- C. 每个线程一个
- D. 每个数据库调用一个

**答案**：A

**解析**：一次外部请求对应一个全局 TraceId，链路上每个调用单元对应一个 Span，Span 都归属于该 TraceId。

**对应知识点**：链路追踪

### 判断题

**1. 雪崩效应的典型表现是下游变慢导致上游线程被占满，故障沿调用链逐层放大。**

**答案**：正确

**解析**：正确。这正是雪崩效应的传导机制，超时、熔断、限流与舱壁隔离都是为了阻断这条传导链。

**对应知识点**：雪崩效应

**2. 任何远程调用都必须显式设置超时时间，这是容错的基础保障。**

**答案**：正确

**解析**：正确。不设置超时会导致线程被无限期占用，是雪崩最常见的起点。

**对应知识点**：超时控制

**3. 评估系统响应体验时，关注平均延迟比关注 P99 延迟更有意义。**

**答案**：错误

**解析**：错误。平均值会掩盖长尾问题，而慢请求集中的 P99 才更贴近真实用户体验。

**对应知识点**：可观测性
