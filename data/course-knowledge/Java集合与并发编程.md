# Java 集合与并发编程

> 知序学堂演示课程资料（Demo）。本文件同时用于「课程目录」与「课程 AI 助教知识库」。

## 课程简介

本课程围绕 Java 集合框架与并发编程两大核心主题展开。集合部分讲解 List、Set、Map 的接口语义、
典型实现与选型方法；并发部分讲解线程模型、线程安全、同步机制与并发工具类。
学习完成后，应能够根据业务场景选择合适的集合类型，并写出线程安全的并发代码。

**适合人群**：已掌握 Java 基础语法、了解面向对象编程的学习者。

## 第一章 Java 集合框架

本章目标：掌握集合框架的整体结构，理解 List、Set、Map 三大接口的语义差异与典型实现，能够根据场景做出正确选型。

### 1.1 集合框架概览

Java 集合框架主要由两大顶层接口构成：

- `Collection`：单列集合，包含 `List`、`Set`、`Queue` 三个子接口。
- `Map`：双列集合，以键值对（key-value）形式存储数据。

核心接口的语义差异：

| 接口 | 是否有序 | 是否允许重复 | 典型实现 |
| --- | --- | --- | --- |
| List | 有序（按索引） | 允许 | ArrayList、LinkedList |
| Set | 通常不保证 | 不允许 | HashSet、LinkedHashSet、TreeSet |
| Map | 不保证 / 可保证 | key 不重复 | HashMap、LinkedHashMap、TreeMap |
| Queue | 按队列规则 | 允许 | ArrayDeque、PriorityQueue |

选型的基本原则：先确定「是否需要按 key 查找」「是否需要去重」「是否需要保持顺序」，
再决定使用哪一类集合。

### 1.2 List 集合

List 是最常用的集合类型，特点是**有序、可重复、支持索引访问**。

**ArrayList**

- 底层是动态数组，支持随机访问，`get(index)` 时间复杂度为 O(1)。
- 扩容时按约 1.5 倍增长，中间位置插入/删除需要移动元素，代价较高。
- 适合：读多写少、以随机访问为主的场景。

**LinkedList**

- 底层是双向链表，插入/删除只需调整指针，不需要移动元素。
- 随机访问需要从头遍历，`get(index)` 时间复杂度为 O(n)。
- 同时实现了 `Deque`，可作为队列或栈使用。
- 适合：频繁在两端或中间插入/删除的场景。

**对比与选型**

| 操作 | ArrayList | LinkedList |
| --- | --- | --- |
| 随机访问 get(i) | 快，O(1) | 慢，O(n) |
| 尾部插入 | 快（均摊 O(1)） | 快 |
| 中间插入/删除 | 慢，O(n) | 快（已定位时 O(1)） |
| 内存占用 | 较小 | 每个节点额外存前后指针 |

结论：绝大多数业务场景优先使用 `ArrayList`；只有当插入删除非常频繁，
且随机访问很少时，才考虑 `LinkedList`。

### 1.3 Set 集合

Set 的核心语义是**元素不重复**，常用于去重和集合运算。

**HashSet**

- 基于 `HashMap` 实现，元素作为 key 存储。
- 不保证遍历顺序，去重依赖 `hashCode()` 与 `equals()`。
- 使用自定义对象时，必须同时重写 `hashCode()` 和 `equals()`，否则去重会失效。

**LinkedHashSet**

- 继承自 HashSet，内部额外维护一条双向链表记录插入顺序。
- 遍历顺序等于插入顺序，性能略低于 HashSet。

**TreeSet**

- 基于红黑树实现，元素按自然顺序或自定义 `Comparator` 排序。
- 插入、删除、查找时间复杂度为 O(log n)。
- 适合需要有序遍历或范围查询的场景。

**去重原理**：向 HashSet 添加元素时，先比较 `hashCode()` 定位桶，
再在桶内用 `equals()` 比较，两者都相同才视为重复。

### 1.4 Map 集合

Map 存储键值对，key 不允许重复，相同 key 再次 put 会覆盖旧值。

**HashMap**

- 底层是「数组 + 链表 + 红黑树」结构。
- 默认初始容量 16，负载因子 0.75，超过阈值触发扩容为 2 倍。
- 当单个桶内链表长度达到 8 且数组长度不小于 64 时，链表转为红黑树，查询效率从 O(n) 提升到 O(log n)。
- 非线程安全，多线程并发写入可能导致数据不一致。

**LinkedHashMap**

- 在 HashMap 基础上增加双向链表，可保持插入顺序或访问顺序。
- 把 `accessOrder` 设为 true 时按访问顺序排列，可用于实现简易 LRU 缓存。

**TreeMap**

- 基于红黑树，key 按顺序排列，支持 `firstKey()`、`floorKey()` 等范围操作。

**遍历方式**：推荐使用 `entrySet()` 遍历，避免用 `keySet()` 逐个 `get()`，
后者在数据量大时会产生额外查找开销。

### 1.5 本章小结

- List 关注顺序与索引，ArrayList 是默认选择。
- Set 关注去重，HashSet 最常用，需要顺序时用 LinkedHashSet。
- Map 关注键值映射，HashMap 是默认选择。
- 自定义对象放入 HashSet 或作为 HashMap 的 key 时，必须正确重写 `hashCode()` 与 `equals()`。

## 第二章 并发编程基础

本章目标：理解线程的创建与生命周期，掌握线程安全问题的成因，能够使用 synchronized、
并发集合和原子类编写正确的并发代码。

### 2.1 线程基础

**线程的创建方式**

1. 继承 `Thread` 类并重写 `run()`。
2. 实现 `Runnable` 接口，交给 Thread 执行（推荐，避免单继承限制）。
3. 实现 `Callable` 接口，配合线程池使用，可获取返回值与抛出异常。

**线程的生命周期**

新建（NEW）→ 就绪（RUNNABLE）→ 运行 → 阻塞（BLOCKED / WAITING / TIMED_WAITING）→ 终止（TERMINATED）。

**线程池**

频繁创建销毁线程开销较大，生产环境应使用线程池管理。`ThreadPoolExecutor` 的核心参数：

- `corePoolSize`：核心线程数
- `maximumPoolSize`：最大线程数
- `keepAliveTime`：空闲线程存活时间
- `workQueue`：任务队列
- `threadFactory`：线程工厂
- `rejectedExecutionHandler`：拒绝策略

任务提交顺序：核心线程 → 任务队列 → 非核心线程 → 拒绝策略。

注意：不要使用 `Executors.newFixedThreadPool()` 创建无界队列线程池，
队列无限增长可能导致内存溢出，建议直接使用 `ThreadPoolExecutor` 并指定有界队列。

### 2.2 线程安全与竞态条件

**什么是竞态条件**

多个线程同时读写共享变量，最终结果依赖线程执行的相对时序，导致结果不确定。

典型例子：`count++` 实际包含「读取 → 加一 → 写回」三个步骤，
两个线程同时执行时可能都读到旧值，导致一次自增丢失。

**三大特性**

| 特性 | 含义 | 保障手段 |
| --- | --- | --- |
| 原子性 | 操作不可分割 | synchronized、Lock、原子类 |
| 可见性 | 修改对其他线程立即可见 | volatile、synchronized |
| 有序性 | 指令不被随意重排 | volatile、synchronized |

**volatile 的作用与局限**

- 保证可见性与一定的有序性（禁止指令重排）。
- **不保证原子性**：`volatile int i; i++` 仍然不是线程安全的。
- 适用场景：状态标志位、一次性安全发布。

### 2.3 synchronized 同步

**三种用法**

1. 修饰实例方法：锁是当前对象实例。
2. 修饰静态方法：锁是当前类的 Class 对象。
3. 修饰代码块：锁是括号中指定的对象。

**原理简述**

synchronized 通过对象头中的 Monitor 实现，进入时获取锁、退出时释放锁。
JDK 6 之后引入了偏向锁、轻量级锁、重量级锁的升级过程来优化性能。

**注意事项**

- 锁对象必须是同一个对象，否则起不到互斥作用。
- 缩小同步范围可以提高并发性能，只锁必要的代码。
- 避免嵌套锁导致的死锁；如果必须多把锁，保证所有线程按相同顺序获取。

### 2.4 并发集合

普通集合（ArrayList、HashMap）不是线程安全的，并发场景应使用 JUC 包提供的并发集合。

**ConcurrentHashMap**

- 线程安全的 HashMap 替代品。
- JDK 8 采用 CAS + synchronized 锁单个桶，并发度远高于早期版本的分段锁。
- 读取操作基本无锁，写入只锁当前桶。
- 不允许 null 键和 null 值。

**CopyOnWriteArrayList**

- 写操作时复制整个数组，读操作无锁。
- 适合读多写极少、数据量不大的场景，如监听器列表。
- 写操作开销大，不适合频繁写入。

**常用并发工具**

| 工具 | 作用 |
| --- | --- |
| CountDownLatch | 等待多个线程完成任务 |
| CyclicBarrier | 多个线程互相等待到齐后继续 |
| Semaphore | 控制同时访问资源的线程数量 |
| BlockingQueue | 阻塞队列，常用于生产者消费者模型 |

**原子类**

`AtomicInteger`、`AtomicLong` 等基于 CAS 实现无锁原子操作：

- `incrementAndGet()`：原子自增，替代 `synchronized` 的简单计数场景。
- `compareAndSet(expected, update)`：CAS 核心方法。
- 高并发下 CAS 会自旋重试，可使用 `LongAdder` 进一步提升性能。

### 2.5 本章小结

- 线程池是管理线程的标准做法，避免使用无界队列。
- 竞态条件源于共享可变状态，解决思路是「不共享」或「正确同步」。
- volatile 只保证可见性，不保证原子性。
- 并发场景优先使用 ConcurrentHashMap、原子类，而非给普通集合加锁。
- 死锁的预防关键是统一加锁顺序、缩小锁范围。

## 综合练习

### 选择题

**1. 需要按键快速查找对应值时，优先选择哪类集合？**
A. List　B. Map　C. Queue　D. Stack
答案：B。Map 以键值对保存数据，适合通过 key 查找 value。

**2. HashSet 允许重复元素并保持插入顺序，这个说法是否正确？**
A. 正确　B. 错误
答案：B。HashSet 用于去重且不保证顺序，需要插入顺序请使用 LinkedHashSet。

**3. 多个线程同时修改同一共享变量，最需要关注什么问题？**
A. 竞态条件　B. 类加载顺序　C. 字符串常量池　D. 包命名规范
答案：A。执行时序不确定会导致结果错误，需要同步或原子操作。

**4. 关于 volatile，下列说法正确的是？**
A. 保证原子性
B. 只保证可见性和一定有序性，不保证原子性
C. 可以替代所有 synchronized
D. 能让 i++ 线程安全
答案：B。

### 判断题

**5. ConcurrentHashMap 通常比给整个 HashMap 加一把大锁有更好的并发性能。**
答案：正确。它采用更细粒度的锁，减少线程间不必要的阻塞。

**6. 使用 Executors.newFixedThreadPool() 创建线程池是生产环境的最佳实践。**
答案：错误。该方法使用无界队列，任务积压可能导致内存溢出，建议使用 ThreadPoolExecutor 指定有界队列。

### 简答题

**7. 请简述 ArrayList 和 LinkedList 的主要差异。**
参考答案：ArrayList 基于动态数组，随机访问快（O(1)），中间插入删除慢；
LinkedList 基于双向链表，已定位时插入删除快，随机访问慢（O(n)）。
实际选型应结合访问模式与数据规模判断。

**8. 为什么不能只依赖 volatile 保证 i++ 的线程安全？**
参考答案：volatile 保证可见性和一定有序性，但 i++ 是「读-改-写」复合操作，
不具备原子性，并发执行时仍会丢失更新。可改用 synchronized 或 AtomicInteger。

**9. 使用自定义对象作为 HashMap 的 key 时，必须注意什么？**
参考答案：必须同时正确重写 hashCode() 与 equals()。
只重写其一会导致去重失效或查找不到，因为 HashMap 先按 hashCode 定位桶，再用 equals 比较。

**10. 简述死锁产生的四个必要条件，并给出一种预防思路。**
参考答案：互斥、持有并等待、不可剥夺、循环等待。
预防思路：统一所有线程的加锁顺序，破坏循环等待条件；或使用带超时的 tryLock 避免无限等待。
